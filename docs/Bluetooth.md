# 蓝牙戒指连接与调试方案

## 功能点

- 扫描附近有效戒指设备。
- 识别已连接或正在连接的戒指状态。
- 展示可连接的设备列表。
- 点击设备后连接戒指并完成初始化。
- 扫到目标设备时展示类似 AirPods 的底部弹窗。
- 记录真实 CoreBluetooth 回调、TX 写入和 RX 数据。

## 有效设备识别

不能只依赖名称包含 `T3`。当前先使用两级判断：

1. 设备名称包含 `T3`。
2. 广播 service UUID 包含 `FFF0`。

两者满足任意一个就认为是候选戒指设备。后续连接后必须继续校验：

- Service UUID：`0xFFF0`
- TX Characteristic：`0xFFF6`
- RX Characteristic：`0xFFF7`

如果名称匹配但连接后找不到 `FFF0/FFF6/FFF7`，应标记为无效设备并展示错误；不能假装连接成功。

## 扫描前状态检查

点击扫描或连接前，先判断当前状态：

- 如果已经连接到名称包含 `T3` 或已发现 `FFF0` 的设备，提示“戒指已连接”，不要继续扫描。
- 如果正在扫描，允许用户停止扫描。
- 如果蓝牙未开启，展示系统状态，例如 `poweredOff`。
- 如果蓝牙未授权，提示用户去系统设置开启蓝牙权限。

注意：iOS 上已连接的 BLE 外设不一定会继续广播，所以“已经连接时扫描不到”是正常现象。页面需要明确告诉用户当前已连接，而不是展示空列表。

## 扫描列表

扫描列表只展示候选设备：

- 名称
- RSSI
- 广播 service UUID
- 连接按钮

列表排序按 RSSI 从强到弱。重复发现同一个 peripheral 时更新 RSSI，不新增重复行。

空状态文案：

> 未发现有效戒指。请确认戒指已开机、靠近手机，并且未被其他手机连接。

## 底部弹窗

当扫描到候选戒指时，弹出类似 AirPods 的底部面板：

- 从底部滑入。
- 显示戒指名称和连接状态。
- 显示一个戒指视觉图。
- 显示“连接”按钮。
- 连接中展示进度状态。
- 连接成功后切换为“已连接，等待按下戒指”。

视觉资源建议：

- 第一版用本地 SVG 或 PDF vector asset 表示戒指。
- 动画使用 SwiftUI `rotationEffect` 和 `withAnimation` 实现持续旋转。
- 后续如果需要更真实的质感，再替换成 PNG 或 3D 渲染图。

不要用纯文字弹窗；这个弹窗是给用户确认“这就是要连接的戒指”的主交互。

## 连接流程

连接有两个入口。

入口一：点击“连接戒指”，由 App 自动扫描并连接目标戒指：

1. 检查当前是否已经连接戒指。
2. 检查蓝牙状态是否为 `poweredOn`。
3. 开始扫描附近 BLE 设备。
4. 过滤候选设备：名称包含 `T3`，或广播 service UUID 包含 `FFF0`。
5. 扫描到第一个候选设备后，停止扫描。
6. 调用 `central.connect(peripheral)` 准备连接。
7. `didConnect` 后发现 service `FFF0`。
8. 发现 characteristic `FFF6` 和 `FFF7`。
9. 订阅 RX `FFF7`。
10. 写入初始化指令到 TX `FFF6`。
11. 等待写入成功回调。
12. 页面进入“已连接”状态。

入口二：用户先点击“扫描”，再从扫描列表里选择设备：

1. App 持续扫描并更新候选设备列表。
2. 用户点击某一行的“连接”。
3. App 停止扫描。
4. 调用 `central.connect(peripheral)` 准备连接。
5. 后续流程同入口一的第 7 到 12 步。

任何一步失败都进入失败状态，并把错误写入链路日志。

## 协议摘要

来自 `T3_API_20260114.pdf` 和现有 demo 文档：

- Service UUID：`0xFFF0`
- TX UUID：`0xFFF6`，App 发给戒指。
- RX UUID：`0xFFF7`，戒指发给 App。
- 常规命令包长度：16 bytes。
- `B1` 是命令。
- `B2...B15` 是载荷。
- `B16` 是 CRC。
- CRC：前 15 个字节求和后取低 8 位，即 `sum(bytes[0...14]) & 0xFF`。

设备返回规则：

- 校验正确时返回原命令号。
- CRC 错误时把命令号 Bit 7 置 1 后返回。

## 命令表

### 设置不压缩音频

用途：要求戒指发送不压缩 PCM，便于 App 直接组 WAV。

```text
0x4A 0x01 0x00 ... CRC
```

字段：

- `0x4A`：音频压缩选择。
- `AA = 0x01`：写入配置。
- `BB = 0x00`：不压缩。

### 设置 HID 录音模式

用途：把戒指按键切到录音入口。

```text
0x1C AA BB 0x04 DD EE FF ... CRC
```

已知点：

- `CC = 0x04` 表示录音模式。
- `AA/BB/DD/EE/FF` 的完整含义还需要实机确认。

当前 demo 先发送：

```text
0x1C 0x00 0x00 0x04 0x00 ... CRC
```

### 打开录音发送

用途：要求戒指开始发送音频。

```text
0xC9 0x01 0x00 ... CRC
```

### 关闭录音发送

用途：结束当前音频发送。

```text
0xC9 0x00 0x00 ... CRC
```

### 戒指开始录音事件

方向：戒指通过 RX 发给 App。

```text
0xC9 0x03 ... CRC
```

含义：设备检测到开始录音。

### 戒指结束录音事件

方向：戒指通过 RX 发给 App。

```text
0xC9 0x04 ... CRC
```

含义：设备音频数据结束。

### 震动 200ms

用途：录音结束后给用户触感反馈。

```text
0x08 0x02 0x00 ... CRC
```

字段：

- `0x08`：震动命令。
- `AA = 0x02`：震动 200 ms。

## 音频数据

RX `FFF7` 会推送音频数据。

不压缩 PCM 格式：

```text
CA ID1 ID2 D1 D2 ... D240
```

含义：

- `CA`：音频数据包标识。
- `ID1 ID2`：包序号。
- `D1...D240`：PCM 数据，每包 120 个采样点。

目标格式：

- 单声道。
- 16 bit。
- 16 kHz。

App 需要做：

1. 校验包序号。
2. 按序拼接 PCM。
3. 生成 WAV。
4. 送入语音转文字。

## 页面状态

建议状态：

- `disconnected`：未连接。
- `scanning`：扫描候选戒指。
- `connecting`：正在连接 peripheral。
- `discovering`：正在发现服务和特征。
- `connected`：已连接并初始化完成。
- `recording`：已打开录音发送。
- `receiving`：正在接收音频包。
- `ready`：本次录音已结束，可进入 AI 处理。
- `failed`：明确展示失败原因。

错误不做静默兜底，不展示假成功。

## 当前实现对照

当前代码已覆盖：

- 扫描候选设备：名称含 `T3` 或广播 `FFF0`。
- 扫描列表展示名称、RSSI、Service。
- 点击设备连接。
- 连接后发现 `FFF0/FFF6/FFF7`。
- 订阅 RX `FFF7`。
- 发送初始化、录音、停止、震动指令。
- 链路日志记录 CoreBluetooth 回调和 TX/RX 数据。

还未完成：

- 类 AirPods 的底部弹窗。
- 戒指图片/动画资源。
- PCM 缓存、WAV 生成和 STT 接入。

## 待实机验证

- 名称包含 `T3` 是否覆盖所有戒指型号。
- 广播 service 是否稳定包含 `FFF0`。
- 已连接戒指是否停止广播。
- `0x1C` 录音模式需要的完整参数。
- 按下戒指是否主动返回 `0xC9 03`。
- 松开戒指是否主动返回 `0xC9 04`。
- HID 录音模式下是否仍需 App 发送 `0xC9 01`。
- 关闭音频发送后立即震动是否稳定。
- 不压缩 PCM 的 BLE 吞吐是否足够。
