# 蓝牙戒指语音 Demo 链路

## Demo 目标

这个 demo 先跑通一条完整链路：

1. App 连接蓝牙戒指。
2. 用户按下戒指按钮。
3. 戒指开始采集音频并通过 BLE 发给 App。
4. App 收到音频后转文字。
5. AI 对文字做润色和意图识别。
6. App 把结果展示成索引卡。
7. 如果识别为定时提醒，App 请求通知权限并创建本地通知。
8. 录音结束时，App 给戒指发送结束录音指令和震动指令。

## Demo 边界

本阶段只做单设备、单用户、单次短语音闭环。

必须包含：

- 蓝牙连接状态。
- 戒指触发录音。
- 音频接收状态。
- 文本润色结果。
- 意图分类结果。
- TODO、定时、长期素材三类卡片。
- 定时提醒的本地通知权限申请。
- 录音结束后的戒指震动反馈。

暂不包含：

- 多设备同步。
- 团队协作。
- 复杂知识图谱。
- 云端账户体系。
- 长录音和后台常驻录音。

## 蓝牙协议摘要

来自 `T3_API_20260114.pdf` 的 demo 相关信息：

- Service UUID：`0xFFF0`
- TX UUID：`0xFFF6`，App 发送数据给戒指。
- RX UUID：`0xFFF7`，戒指发送数据给 App。
- 常规命令包长度：16 bytes。
- 包结构：`B1` 是命令，`B2...B15` 是载荷，`B16` 是 CRC。
- CRC 算法：前 15 个字节求和后取低 8 位，公式为 `sum(bytes[0...14]) & 0xFF`。
- 如果命令校验正确，设备返回原命令号；如果 CRC 错误，设备把 Bit 7 置 1 后返回。

## Demo 用到的指令

### 音频发送

命令：`0xC9 AA 00 00 00 00 00 00 00 00 00 00 00 00 00 CRC`

含义：

- `AA = 1`：打开录音发送功能。
- `AA = 0`：关闭录音发送功能。
- `AA = 3`：设备开始检测时返回。
- `AA = 4`：音频数据结束时返回。

音频格式：

- 单声道。
- 16 bit。
- 16 kHz 采样率。
- 不压缩格式：`CA ID1 ID2 D1 D2 ... D240`，每包 120 个采样点。
- 压缩格式：`CA ID1 ID2 LL D1 D2 ... Dxxx`，每条表示 40 ms 音频，当前压缩格式为 Opus 1.3.1。

Demo 优先使用不压缩 PCM，App 可以直接组装 WAV 并送入语音转文字。若设备只返回压缩数据，demo 需要先接入 Opus 解码。

### 音频压缩选择

命令：`0x4A AA BB 00 00 00 00 00 00 00 00 00 00 00 00 CRC`

含义：

- `AA = 1`：写入配置。
- `AA = 0`：读取配置。
- `BB = 0`：不压缩。
- `BB = 1`：压缩。

Demo 启动连接后，App 先发送 `0x4A 01 00 ... CRC`，要求设备使用不压缩音频。

### HID 录音模式

命令：`0x1C AA BB CC DD EE FF 00 00 00 00 00 00 00 00 CRC`

手册标注 `CC = 4` 为录音模式。Demo 连接后，App 将戒指切到录音模式，用戒指按键作为录音入口。

需要实机确认的点：

- 戒指按下后是否直接通过 `0xC9` 返回 `AA = 3`。
- 戒指松开后是否通过 `0xC9` 返回 `AA = 4`。
- HID 录音模式下是否仍需要 App 主动发送 `0xC9 01`。

### 震动反馈

命令：`0x08 AA BB CC 00 00 00 00 00 00 00 00 00 00 00 CRC`

含义：

- `AA = 1`：震动 50 ms。
- `AA = 2`：震动 200 ms。
- `AA = 3`：震动 500 ms。
- `AA = 4`：震动 1000 ms。
- `AA = 5`：使用 `BB CC` 设置震动时长，单位 ms。
- `AA = 0x99`：测试模式。

Demo 采用 `AA = 2`，录音结束后震动 200 ms。

## 交互数据流

### 初始化

1. App 请求蓝牙权限。
2. App 扫描 Service `0xFFF0`。
3. App 连接戒指。
4. App 订阅 RX `0xFFF7`。
5. App 写入 TX `0xFFF6`，设置音频不压缩：`0x4A 01 00 ... CRC`。
6. App 写入 TX `0xFFF6`，设置 HID 录音模式：`0x1C ... CC=4 ... CRC`。
7. App 展示“已连接，等待按下戒指”。

### 开始录音

1. 用户按下戒指按钮。
2. 戒指向 App 返回录音开始事件，预期为 `0xC9 03 ... CRC`。
3. App 进入 `recording` 状态。
4. App 展示录音动效和计时。
5. App 开始缓存 RX 音频包。

如果实机确认按下戒指不会主动返回开始事件，App 在检测到按键事件后发送 `0xC9 01 ... CRC` 打开音频发送。

### 接收音频

1. 戒指持续通过 RX `0xFFF7` 推送音频数据。
2. App 校验数据包序号。
3. App 按序拼接 PCM。
4. App 在内存或临时文件中生成 WAV。
5. App 保持 UI 为“接收中”。

Demo 先要求短语音，建议限制 3 到 15 秒。超过 15 秒时 App 主动发送 `0xC9 00 ... CRC` 结束本次录音。

### 结束录音

1. 用户松开戒指按钮，或戒指完成本次音频发送。
2. 戒指返回音频结束事件，预期为 `0xC9 04 ... CRC`。
3. App 停止缓存音频。
4. App 发送 `0xC9 00 ... CRC`，关闭录音发送。
5. App 等待设备返回 `0xC9 00 ... CRC`。
6. App 发送 `0x08 02 ... CRC`，触发 200 ms 震动。
7. App 进入 `processing` 状态。

这个顺序让设备先结束音频流，再执行触感反馈，避免震动指令和音频数据混在同一段状态里。

### AI 处理

1. App 把 WAV 送入语音转文字。
2. App 将原始文本发给 AI。
3. AI 返回润色文本和意图分类。
4. App 根据分类生成索引卡。

Demo 分类先收敛为三类：

- `todo`：需要执行的行动。
- `reminder`：有明确时间或相对时间。
- `material`：灵感、备忘、长期素材。

AI 返回结构建议：

```json
{
  "rawText": "明天下午三点提醒我给客户发方案",
  "polishedText": "明天下午三点提醒我给客户发送方案。",
  "intent": "reminder",
  "title": "给客户发送方案",
  "remindAt": "2026-05-16T15:00:00+08:00"
}
```

### 提醒创建

1. App 判断 `intent = reminder`。
2. App 检查通知权限。
3. 没有权限时，App 请求 `UNUserNotificationCenter` 授权。
4. 用户授权后，App 创建本地通知。
5. App 卡片展示提醒时间和系统权限状态。

如果用户拒绝通知权限，App 仍展示提醒卡片，但状态标记为“未开启系统通知”。

## App 状态机

- `idle`：未连接或等待连接。
- `connected`：已连接，等待戒指按下。
- `recording`：正在录音并接收音频。
- `processing`：正在转文字和识别意图。
- `ready`：结果已生成。
- `error`：展示错误并允许重试。

错误只做明确呈现，不做静默兜底。

## Demo 页面

首屏保留一个可演示的工作台：

- 顶部：设备连接状态、电量、当前模式。
- 中部：录音状态、计时、音频包数量。
- 下方：AI 结果卡片。
- 底部：手动调试按钮，包括连接、模拟按下、模拟结束、发送震动。

手动调试按钮用于没有实机或协议未完全验证时演示链路。实机链路验证后，调试按钮放入 Debug 面板。

## 验收标准

- App 能连接 Service `0xFFF0` 的戒指。
- App 能收到戒指按下后的录音开始事件。
- App 能接收一段音频并生成文本。
- App 能展示润色文本和意图分类。
- TODO 卡片能保留待办标题。
- 定时卡片能申请通知权限并创建本地通知。
- 录音结束后，戒指能收到关闭音频发送指令。
- 录音结束后，戒指能震动 200 ms。

## 待实机验证

- `0x1C` 录音模式的完整参数。
- 按下戒指时的实际 RX 事件。
- 松开戒指时的实际 RX 事件。
- `0xC9` 音频包是否和普通 16 bytes 命令包共用 CRC 规则。
- 不压缩 PCM 的 BLE 吞吐是否足够。
- 震动指令能否在关闭音频发送后立即执行。
