# 录音链路说明

## 目标

戒指侧会持续推送音频 Buffer，App 端不要按每个 Buffer 立刻刷新 UI。更稳妥的做法是先缓存，再按固定节奏批量转写，这样既能保留接近实时的体验，又能控制界面刷新频率。

## 处理流程

1. RX 收到原始音频 Buffer。
2. App 只做轻量处理：校验顺序、写入队列。
3. 每 2 秒从队列中取出一段连续音频。
4. 将 Buffer 按顺序拼成 PCM 流，必要时组装成 WAV。
5. 把音频片段送入语音转文字服务。
6. 将识别结果合并成中文 transcript，刷新到 UI。

## Buffer 如何变成文字

Buffer 本身不是文字，而是原始音频数据。转换过程可以理解为：

```text
BLE Buffer -> PCM 缓存 -> 音频片段 -> WAV/STT -> 中文文本 -> 页面展示
```

其中最关键的是两步：

- 先保证音频包顺序正确，避免丢包或乱序。
- 再把连续音频片段送入 STT，而不是逐包识别。

## UI 更新策略

- UI 只展示当前最新识别结果，不要每来一个 Buffer 就刷新。
- 采用 2 秒一次的批量刷新，能保留实时感，也能降低卡顿和重绘频率。
- 最终识别结果落定后，再写入完整文本或摘要。

## 结论

戒指侧是流式 Buffer 传输，App 端应采用“缓冲队列 + 定时批量识别”的方式处理。文档里需要明确区分三件事：原始音频 Buffer、转写后的文本、页面最终展示的结果。
